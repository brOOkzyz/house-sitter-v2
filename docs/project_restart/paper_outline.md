# Paper outline

1. **Introduction and Project25 background** — idle domestic-vacuum capacity, monitoring/Digital Twin goals, and evidence boundary.
2. **Problem and RaPToR-Lite** — capability-grounded structured task creation, verification, traceability and why the layer is intentionally small.
3. **System design** — registry, schema, verifier, deterministic backend abstraction and House-Sitter integration.
4. **Simulation-first methodology** — seeded 2D household generator, ground truth, artifacts, metrics and paired comparisons.
5. **Evaluation** — RQ1 verifier effectiveness, RQ2 task-creation reliability, RQ3 House-Sitter reliability.
6. **House-Sitter case study** — anomaly, Digital Twin, alert and report traceability; optional visual demonstration clearly separated from evaluation.
7. **Limitations and future physical deployment** — synthetic sensors, model/backend limits, no physical-robot claims, and criteria for a later deployment study.
8. **Conclusion** — bounded contribution and reproducible evidence.

The original RaPToR draft is cited as motivation/source material only; it is not reported as the present codebase or evidence base.
